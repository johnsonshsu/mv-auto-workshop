## 1. 系統架構與模組職責

```

└───────────────▲──────────────────────────────┬──────────────────┘
        Qt 訊號（進度、記錄、狀態）            │ 指令（開始/暫停/取消/重跑）
┌───────────────┴──────────────────────────────▼──────────────────┐
│ 流程編排層  PipelineRunner（背景 QThread）                        │

└───────────────┬──────────────────────────────────────────────────┘
                │ 每個階段實作同一介面 Stage
┌───────────────▼──────────────────────────────────────────────────┐
│ 服務層                                                            │
│  ComfyClient（HTTP+WS）  WorkflowTemplate（範本+對應表注入）      │
│  LLMClient（Ollama / Claude / OpenAI 相容）  AlignService（子程序）│
│  FFmpegService   HardwareProbe   LipSyncEngine（InfiniteTalk/LTX）│
└───────────────┬──────────────────────────────────────────────────┘
┌───────────────▼──────────────────────────────────────────────────┐
│ 儲存層  ProjectStore（專案資料夾、project.json 原子寫入）          │

└──────────────────────────────────────────────────────────────────┘
```

### Stage 共同介面

```python
class Stage(Protocol):
    id: str                                   # "s3_song"
    def check_inputs(self, ctx) -> list[Problem]   # 需要的檔案是否齊全
    def run(self, ctx, reporter) -> StageResult    # 從頭執行
    def resume(self, ctx, reporter) -> StageResult # 從中斷處接續（預設等同 run）
    def outputs(self, ctx) -> list[Path]           # 回報產出檔
```

`ctx` 只提供專案資料夾路徑、設定與服務；階段之間不傳記憶體物件，只讀寫檔案。

## 2. 七階段資料流

| 階段 | 讀取 | 寫入 | 外部呼叫 |
| --- | --- | --- | --- |
| S1 環境偵測 | `config/thresholds.toml`、`workflows/*.requires.json` | `env_report.json` | nvidia-smi、ComfyUI `/system_stats` `/object_info`、ffmpeg |
| S2 歌詞 | `project.json`（內容、曲風、語言、長度、範本） | `lyrics/lyrics.json`、`lyrics/lyrics.txt` | LLM（AI 模式） |
| S3 歌曲 | `lyrics/lyrics.json` | `audio/song.flac`、`audio/yue2_prompt.json` | LLM（Style）、ComfyUI（YuE2） |
| S4 字幕 | `audio/song.flac`、`lyrics/lyrics.txt`、`lyrics/lyrics.json` | `audio/vocals.wav`、`audio/instrumental.wav`、`lyrics/lyrics.srt`、`analysis/sections.json`、`analysis/alignment_report.json` | ComfyUI（人聲分離）、對齊子程序 |
| S5 影片 | `input/photo_原檔`、`audio/vocals.wav`、`audio/song.flac`、`analysis/sections.json` | `input/photo_prepared.png`、`analysis/video_prompt.json`、`analysis/segment_plan.json`、`segments/seg_NNN.mp4`、`output/video_nosub.mp4` | LLM（影像提示詞）、ComfyUI（對嘴引擎）、FFmpeg |
| S6 合成 | `output/video_nosub.mp4`、`lyrics/lyrics.srt`、字幕樣式 | `output/final_mv.mp4` | FFmpeg |
| S7 匯出 | 全部產出 | 專案根目錄的 `final_mv.mp4`、`song.flac`、`lyrics.txt`、`lyrics.srt`、`video_nosub.mp4`（硬連結或複製）、`logs/summary.json` | 無 |

S3 的「歌詞是否唱完」檢查需要 S4 的對齊結果，所以 S3、S4 在編排層是一個重試迴圈：S4 回報未對齊行數超過門檻（預設 >15% 的行）時，編排層把 S3 標成需重試、換 seed 再跑，最多 3 次（可設定）。超過上限後取未對齊最少的那一版，全自動模式記警告繼續，逐步確認模式停下來問。

**依賴與過期規則**（上游改了，下游標為「已過期」）：

```
輸入(內容/曲風/範本) → S2 → S3 → S4 → S5 → S6 → S7
歌詞手動修改         → S3 以下過期
SRT 手動微調         → S6 以下過期
照片/引擎/解析度     → S5 以下過期
字幕樣式             → 只有 S6 以下過期
```

**VRAM 交接**：呼叫 LLM 後讓 Ollama 卸載（`keep_alive: 0`）；每個 ComfyUI 階段結束呼叫 `POST /free`（`unload_models`、`free_memory`）；對齊子程序啟動前先 `/free`，子程序結束即釋放。

## 3. 資料結構

本節描述實作後的實際格式；欄位名稱與預設值取自程式（`app/core`、`app/storage`、`app/pipeline`）與 `config/default.toml`。

### 3.1 `project.json`

```json
{
  "schema_version": 1,
  "name": "夏夜的風",
  "created_at": "2026-11-10T14:00:00+08:00",
  "mode": "auto",
  "inputs": {
    "content": "描述歌曲主題、故事、情緒的文字",
    "style": "City Pop",
    "language": "zh-TW",
    "vocal_type": "female",
    "voice_character": "",
    "duration_mode": "auto",
    "target_seconds": 150,
    "lyrics_source": "ai",
    "lyric_template": "verse_chorus_bridge",
    "photo": "input/photo_original.jpg",
    "engine": "infinitetalk",
    "resolution": "480p",
    "join_mode": "photo",
    "join_every": 4,
    "anchor_strength": 0.8
  },
  "params": {
    "subtitle_style": { "font": "Noto Sans TC", "size_percent": 7.5, "color": "#FFFFFF", "…": "…" }
  },
  "seeds": { "yue2": 123456, "video": 789012 },
  "stages": {
    "s1_env":   { "status": "done", "started_at": "…", "seconds": 4.2, "warnings": [] },
    "s3_song":  { "status": "done", "seconds": 310.5, "attempts": 2,
                  "warnings": ["歌曲長度達到上限 300 秒，結尾可能沒唱完，已加上 3 秒淡出；…"] },
    "s5_video": { "status": "running", "started_at": "…",
                  "segments": [ { "index": 1, "status": "done", "seconds": 1260.4, "frames": 1501 },
                                { "index": 2, "status": "pending" } ] }
  }
}
```

| 欄位 | 說明 |
| --- | --- |
| `mode` | `auto`（全自動）或 `step`（逐步確認：歌詞產生後、歌曲生成後各停一次） |
| `inputs.language` | 語言代碼，定義在 `config/default.toml` 的 `[languages.*]`：`zh-TW`、`en`、`ja`、`yue` |
| `inputs.vocal_type`、`voice_character` | 男女聲（`female`／`male`）與聲線；聲線是 `[[voices]]` 的 `value`，空字串代表由 LLM 依歌曲內容決定 |
| `inputs.duration_mode`、`target_seconds` | `auto`：由 AI 決定，唱完為止；`max`：歌曲不超過 `target_seconds`。舊專案沒有 `duration_mode`、但有 `target_seconds` 時，視為 `max` |
| `inputs.lyrics_source` | `ai` 或 `manual`；`manual` 時歌詞文字存在 `inputs.manual_lyrics`（歌詞頁儲存） |
| `inputs.yue2_style_override` | 選用。有填就直接當 YuE2 風格描述，不再呼叫 LLM。沒有介面，要改 `project.json` |
| `inputs.join_mode`、`join_every`、`anchor_strength` | 分段銜接方式，見第 6.4 節；沒有指定的項目沿用引擎的設定 |
| `params.subtitle_style` | 只存使用者改過的字幕樣式；沒有的欄位用 `[subtitle]` 的預設值 |
| `seeds.video` | 影片階段的基準 seed，第 *i* 段用 `video + i` |
| `song_takes` | 歌詞沒唱完時重試迴圈的暫存記錄（每版 `{number, ratio}`），迴圈結束後清空 |
| `stages.<id>` | 見下方狀態說明；各階段另有自己的欄位（`attempts`、`segments`、`style`、`error`） |

新專案只帶入 `language`、`duration_mode`、`target_seconds`、`engine`、`resolution` 的預設值，其餘欄位在使用者於輸入頁儲存時才寫入。

`status` 為 `pending`（待執行）、`running`、`done`、`failed`、`stale`（已過期）。開啟專案時若發現 `running`，視為上次被中斷，從該階段 `resume`；續跑起點是第一個不是 `done` 的階段。寫入一律「寫 `project.json.tmp` → `fsync` → `os.replace`」。金鑰不進這個檔，存在 Windows 認證管理員。`schema_version` 比程式新時拒絕開啟。

**過期規則**（上游改了，下游已完成、失敗或執行中的階段標為 `stale`）：

| 改了什麼 | 哪些階段過期 |
| --- | --- |
| 內容、曲風、語言、歌詞來源、歌詞範本 | S2 以後 |

### 3.2 `lyrics.json`

```json
{
  "title": "夏夜的風",
  "language": "zh-TW",
  "sections": [
    { "type": "intro",  "lines": [] },
    { "type": "verse",  "lines": ["巷口的燈一盞一盞亮起", "…"] },
    { "type": "chorus", "lines": ["…"] }
  ]
}
```

`type` 六種：`intro`、`verse`、`prechorus`、`chorus`、`bridge`、`outro`。`lines` 為空代表純音樂段落。
`lyrics.txt` 把所有非空行依序一行一句輸出，**行號（從 1 起）就是字幕編號**，也是字幕文字的唯一來源。

人工輸入解析（`app/core/lyrics.py`）接受的標記：

| 類型 | 中文 | 英文 | YuE2 標記（`[yue2.tag_map]`） |
| --- | --- | --- | --- |
| intro | 前奏 | Intro | `[Verse]` |
| verse | 主歌 | Verse | `[Verse]` |
| prechorus | 導歌、預副歌 | Pre-Chorus | `[Verse]` |
| chorus | 副歌 | Chorus、Hook | `[Chorus]` |
| bridge | 過渡、橋段 | Bridge | `[Bridge]` |
| outro | 尾奏、尾聲 | Outro | `[Outro]` |

- 括號可以是 `[ ]`、`【 】`、`［ ］`、`( )`（全半形都接受）；比對時忽略大小寫、空白、連字號與編號（`[Verse 1]` 等同 `[Verse]`）。純中文標記也可以不加括號（例如單獨一行「副歌2：」）。整行用圓括號包住但不是標記名稱的，視為歌詞（例如和聲），不報錯。
- 看不懂的標記、第一個標記之前的歌詞、完全沒有歌詞，都會逐項指出是第幾行。
- YuE2 官方只列 Verse、Chorus、Bridge、Outro，所以導歌與有歌詞的前奏一律對應到 `[Verse]`；沒有歌詞的段落不寫進 YuE2 的歌詞欄。這個對照表放在設定檔，可以改。
- 歌詞的清理：去掉不唱的標點與括號註解；國語與粵語會用 OpenCC（`s2tw`，只換字、不改用詞）把簡體字轉成繁體，並檢查有沒有 LLM 混入的簡體字。

### 3.3 `sections.json`

```json
{
  "duration": 151.36,
  "sections": [
    { "index": 0, "type": "intro", "start": 0.0,   "end": 12.48, "instrumental": true,  "line_ids": [] },
    { "index": 1, "type": "verse", "start": 12.48, "end": 41.2,  "instrumental": false, "line_ids": [1, 2, 3, 4] }
  ],
  "silences": [ { "start": 40.62, "end": 41.9 }, { "start": 68.1, "end": 69.0 } ]
}
```

段落邊界由各行的對齊時間算出：

- 兩個相鄰的有歌詞段落：邊界取「上一段最後一行的結束」與「下一段第一行的開始」的中點。
- 純音樂段落（`lines` 為空）：佔滿前一段人聲結束到下一段人聲開始之間的空檔，所以它與前後段落的邊界就是人聲的邊界，不取中點。
- 第一段從 0 開始、最後一段到歌曲結束；前面或後面沒有任何人聲段落時也是如此。

`silences` 是 `vocals.wav` 上 RMS 低於門檻（`[silence] threshold_db`，預設 −40 dBFS）且持續 ≥ `min_seconds`（預設 0.4 秒）的區間，以 20 毫秒為單位計算。

### 3.4 工作流對應表與需求清單

`workflows/` 內每個工作流有三個檔案：`<名稱>.api.json`（API 格式工作流）、`<名稱>.map.json`（對應表）、`<名稱>.requires.json`（需求清單）。

對應表（以 YuE2 為例）：

```json
{
  "template": "yue2_text_to_music.api.json",
  "source": "ComfyUI 官方範本 audio_yue2_text2music，由 MV 自動工坊轉為 API 格式",
  "params": {
    "ckpt_name": [{ "node": "15", "input": "ckpt_name" }],
```

### 3.5 歌詞範本

範本是 TOML 文字檔。內建三個在 `config/lyric_templates/`（`verse_chorus_bridge`、`verse_prechorus_chorus`、`short_song`）；使用者新增或修改的存在 `%APPDATA%\MVAutoWorkshop\lyric_templates\`，同代號時使用者的版本蓋過內建（刪除使用者版本後內建版本回來）。

```toml
name = "主歌–副歌–主歌–副歌–過渡–副歌"
style_hint = "口語、畫面感強；主歌說故事，副歌重複一句好記的句子"
rhyme = "每段偶數行押韻，副歌一韻到底"

[[sections]]
type = "verse"
lines = 4
chars_min = 7
chars_max = 11

[[sections]]
type = "chorus"
lines = 4
chars_min = 6
chars_max = 10

[[sections]]
type = "chorus"
repeat_of = 2        # 與第 2 段的歌詞完全相同（段落編號從 1 起）
```

儲存前驗證：`type` 必須是六種之一；`lines` 為 0 到 16 的整數，0 代表純音樂段落；有歌詞的段落 `chars_min`、`chars_max` 必須是 1 到 30 的整數且 `chars_min ≤ chars_max`；`repeat_of` 只能指向前面某個有歌詞、且本身不是重複的段落；至少要有一個有歌詞的段落。

`chars_min`、`chars_max` 是以國語的字數為準，其他語言依 `[languages.*]` 的 `length_factor` 換算（英語 0.7、日語 1.5）。

歌曲長度的估計（`song_seconds`）：先從曲風提示或風格描述找出 BPM（找不到用 96），一行歌詞約兩小節，每行 `480 / BPM` 秒；段落之間的過門再算一行的長度，前奏約 10 秒、尾奏約 6 秒：

```
秒數 = 10 + 行數 × (480 / BPM) + (有歌詞的段落數 − 1) × (480 / BPM) + 6
```

自動模式用它判斷生成結果是否短得不合理（低於估計值 × `song.min_duration_ratio`，預設 0.5，視為失敗並換 seed 重試）；「設定上限」模式用它在寫歌詞前決定要不要從範本後面拿掉段落。

### 3.6 其他產出檔案

## 6. 分段與影格計算

本節描述實作後的行為（`app/core/segmenter.py`、`app/services/engines.py`、`app/pipeline/stages/s5_video.py`、`app/services/ffmpeg_service.py`）。數值取自 `config/default.toml`。

### 6.1 基本原則：一律用累計時間換算

設歌曲長度 `D` 秒、影格率 `fps`，總影格數 `N = round(D × fps)`。
切點時間 `t_0 = 0 < t_1 < … < t_k = D`，對應的影格邊界：

```
F_i = round(t_i × fps)        （強制 F_0 = 0，F_k = N）
第 i 段影格數 n_i = F_i − F_{i-1}
```

每個邊界都是從歌曲起點直接換算，不是把各段長度四捨五入後相加，所以 `Σ n_i = N` 恆成立、誤差不會累積。影格數為 0 的段會被略過。階段開始時還會再檢查一次總和，不符就停止並要求回報。

`fps` 是引擎的設定，因為各模型的影格率不同（見 6.2），所以同一首歌換引擎後 `N` 也不同。

### 6.2 四個引擎的限制

| 設定 | InfiniteTalk 外掛版 | InfiniteTalk 原生版 | LTX-2.3 | Wan 2.2 S2V |
| --- | --- | --- | --- | --- |
| `fps` | 25 | 25 | 24 | 16 |
| 單次生成的影格限制 | 4k + 1 | 72k + 9（K 個視窗得 72(K−1)+81） | 8k + 1 | 80K − 2（K 個區塊） |
| `frame_step`、`frame_offset` | 4、1 | 72、9 | 8、1 | 80、−2 |
| 單段上限 `max_segment_seconds` | 60 | 60 | 10 | 30 |
| 單段下限 `min_segment_seconds` | 3 | 3 | 2 | 3 |
| 預設銜接 | 每 4 段改用照片 | 每 4 段改用照片 | 每段結尾回到照片 | 每段從照片重新開始 |
| 延續段的起始方式 | 上一段最後一幀 | 上一段最後一幀 | 上一段最後一幀 | 上一段最後 73 幀當動作參考 |

單次生成的影格限制由 `valid_frames(need, step, offset)` 處理：回傳滿足 `step × k + offset` 且不小於 `need` 的最小值（`step` 為 1 時不限制）。

### 6.3 切點選擇

輸入：`sections.json` 的段落邊界與 `silences`、該引擎的 `max_seg`、`min_seg`、以及人聲音軌（用來在必要時找最小聲的位置）。

候選切點 = 所有段落的起點與終點（段落邊界）＋ 每個人聲靜音區間的中點。

從位置 `p = 0` 開始，只要剩下的長度大於 `max_seg`，就在範圍 `[p + min_seg, p + max_seg]` 內依下列順序決定下一個切點：

1. 範圍的**後半**（`≥ p + 0.5 × max_seg`）有段落邊界：取其中最靠後的段落邊界。
2. 否則範圍內有任何候選點（段落邊界或靜音中點）：取最靠後的一個。
3. 否則，若範圍內有一段靜音區間跨過範圍（例如很長的前奏或間奏，它的中點在範圍外）：切在這段靜音裡最靠後的位置（不超過 `p + max_seg`）。
4. 都沒有（一句長音超過上限）：在 `[p + 0.6 × max_seg, p + max_seg]` 內，以 0.1 秒為單位找 `vocals.wav` 能量最低的位置**強制切**，並記為強制切點。

收尾：若最後一段短於 `min_seg`，把它併入前一段；併入後若超過 `max_seg`，就把這個切點移到合併範圍的中間（記為強制切點）。

純音樂段落（前奏、間奏、尾奏）同樣切段、同樣由人聲音軌驅動（人聲靜音→不張嘴）。強制切點會在階段結束時列為警告：「第 N 段的起點找不到靜音處，是在人聲中強制切開的」。

### 6.4 每一段從哪裡開始

每段有一個 `init`：

| `init` | 意義 |
| --- | --- |
| `photo` | 以原始照片（前處理後的 `photo_prepared.png`）為起始影像 |
| `prev` | 以上一段**裁切後**的最後一幀（無損 PNG）為起始影像；模型生成的第 1 幀就是這一幀，所以接合時要丟掉 |
| `motion` | 以照片為參考影像，另把上一段最後 `motion_tail_frames` 幀（Wan 2.2 S2V 為 73）當動作參考；模型自己接續，沒有重複影格 |

第一段一定是 `photo`。之後每 `reset_every` 段做一次「校正」，抑制人物越接越不像的累積誤差；`reset_every = 0` 表示完全不校正。校正有兩種方式：

- **`end_anchor = false`（改用照片）**：校正點之後的那一段改以 `photo` 起始。畫面會直接跳接，像換鏡頭。
- **`end_anchor = true`（結尾回到照片）**：前一段的 `end_anchor` 設為真，讓它在結尾回到照片的樣子，下一段照常接續（`prev` 或 `motion`），畫面不跳。只有 LTX-2.3 有對應的工作流（`ltx23_ia2v_anchor`）。

兩種校正都只放在**自然的切點**（段落邊界或人聲靜音處）。若輪到校正時剛好是強制切點，就延後到下一個自然切點；唱到一半被拉回照片的表情會很怪。

使用者在輸入頁選的「分段銜接」存成 `join_mode`、`join_every`、`anchor_strength`，覆蓋引擎的預設：

| `join_mode` | 行為 |
| --- | --- |
| `anchor` | 每一段都以上一段最後一幀起始，每 `join_every` 段讓結尾回到照片的樣子；引擎沒有結尾引導的工作流時退回 `photo` |
| `photo` | 每 `join_every` 段改以原始照片起始，其餘接續上一段 |
| `prev` | 一律接續上一段，不做任何校正（`reset_every` 視為 0） |

`anchor_strength`（0 到 1，預設 0.8）是結尾貼近照片的程度，只用於 `anchor`。引擎預設：`end_anchor` 開啟的引擎預設 `anchor`；否則 `reset_every > 0` 預設 `photo`，等於 0 預設 `prev`。

### 6.5 每段的影格數、音訊與裁切

```
need_i = n_i            起始方式是 photo 或 motion
need_i = n_i + 1        起始方式是 prev（生成的第 1 幀是重複的那一幀，接合時丟掉）
gen_i  = valid_frames(need_i, frame_step, frame_offset)
```

- **送出的音訊**：以驅動音訊（預設 `vocals.wav`，可在 `[video] drive_audio` 改成完整歌曲）切出一段，從 `audio_start_frame − audio_lead_frames` 的時間開始，長度 `gen_i + audio_lead_frames` 個影格。`audio_start_frame` 是 `f_start`（`prev` 段再往前移一幀，對齊重複的那一幀）。超出歌曲開頭或結尾的部分補靜音，存成 16-bit PCM wav。`audio_lead_frames` 是模型輸出比音訊早幾幀的固定偏移：Wan 2.2 S2V 為 2，其他為 0。
- **裁切**：生成後用 FFmpeg 丟掉開頭 `drop_head`（`prev` 段為 1，其餘為 0）幀、保留 `n_i` 幀，重新編碼成統一規格（H.264、yuv420p、固定 fps、無音軌、`crf` 預設 16）；生成的影格不夠時以最後一幀補足並記警告；模型輸出尺寸被取整、與目標不同時縮放成目標尺寸，各段才接得起來。
- **驗證**：裁完用 `ffprobe` 數影格，不等於 `n_i` 就刪除該段並視為失敗。
- **接續用的檔案**：每段完成後存下最後一幀 `segments/last_NNN.png`；`motion` 段則另外把上一段的尾端擷取成短片 `motion_NNN.mp4` 當動作參考，用完刪除。

### 6.6 各引擎如何生成一段

所有引擎都是「一段送一次 ComfyUI 工作流」，差別在於一段內部如何延伸到 `gen_i` 幀：

- **InfiniteTalk 外掛版**：`num_frames = gen_i` 一次送出，由 WanVideoWrapper 的視窗迴圈處理（`frame_window_size` 81、`motion_frame` 9 的重疊）。`blocks_to_swap`（預設 20）決定留在系統記憶體的模型區塊數。
- **InfiniteTalk 原生版**：範本只含一個 81 幀視窗。程式依需要的影格數複製視窗節點（`視窗數 = 1 + ceil((frames − 81) / 72)`），後面的視窗拿前面所有畫面當 `previous_frames`，每個視窗開頭與前面重疊的影格在接上前去掉。
- **Wan 2.2 S2V**：範本只含第一個區塊（77 幀，約 5 秒）。程式複製「延伸區塊」節點（`區塊數 = ceil((frames + 2) / 80)`），每個區塊接在目前為止的潛空間影片後面。有動作參考時，上一段的尾端影片接到第一個區塊。
- **LTX-2.3**：先以一半解析度生成，再放大兩倍精修（兩輪取樣）。段尾要回到照片時（`end_anchor`），改用結尾引導的工作流並帶入照片與 `anchor_strength`。解析度尺寸是 64 的倍數（480p 為 896×512、720p 為 1344×768），其他引擎的 480p 為 832×480。

共同的行為：

- 第 *i* 段的 seed 是 `seeds.video + i`（視窗或區塊內另加偏移）。
- **顯示記憶體不足**：釋放 ComfyUI 的模型後，改用更省 VRAM 的設定重試一次（外掛版 `blocks_to_swap` 改為 `oom_blocks_to_swap`＝40；LTX-2.3 的解碼切塊由 768 改為 512）；仍失敗才回報。
- **暫停**：目前這一段完成後才停下；**取消**：立即中斷。
- 進度與剩餘時間：取樣節點的步數歸零視為進入下一輪，依這次實際生成的速度估算剩餘時間。

### 6.7 分段計畫的保存與續跑

分段計畫存在 `analysis/segment_plan.json`：

```json
{
  "signature": "3f9a1c0d2b7e4a58",
  "engine": "infinitetalk", "fps": 25, "width": 832, "height": 480,
  "duration": 151.36, "total_frames": 3784,
  "prompt": "A singer stands in front of a studio microphone …",
  "segments": [
    { "index": 1, "t_start": 0.0, "t_end": 52.4, "f_start": 0, "f_end": 1310, "frames": 1310,
      "gen_frames": 1313, "init": "photo", "forced_cut": false, "end_anchor": false }
  ]
}
```

`signature` 是下列項目的雜湊：引擎代號、尺寸、fps、`max_segment_seconds`、`reset_every`、`end_anchor`、延續方式、驅動音訊設定、該引擎的全部設定，以及照片、`song.flac`、`sections.json` 三個檔案的內容。

- 階段開始時指紋與舊計畫相同：沿用舊計畫與已完成的段落（段落檔存在且影格數正確就跳過），所以不論是續跑、暫停後繼續或當機後重開，都從未完成的段落接著做；`resume` 與 `run` 是同一個流程。
- 指紋不同（照片、歌曲、段落時間表、引擎、尺寸或任何引擎設定變了）：刪除整個 `segments/`，重新分段、重新產生影像提示詞與 seed。
- 影像提示詞由 LLM 看照片寫成（見第 5.3 節）；LLM 失敗時改用引擎的 `default_prompt` 並記警告。提示詞與計畫一起保存，續跑時不會重寫。

### 6.8 接合與驗證

1. 各段都已重新編碼成相同規格，所以直接用 FFmpeg concat demuxer 接合且不重新編碼（`-c copy -an`）；清單用相對於 `segments/` 的檔名，避開路徑中的空白與中文。
2. 配上 `song.flac` 轉成的 AAC（256 kbps、48 kHz），並把 moov 移到檔頭（`+faststart`），輸出 `output/video_nosub.mp4`。
3. 驗證：
   - 影片總影格數必須等於 `N`，否則停止；
   - 影片長度與歌曲長度相差不得超過 1 個影格，否則停止；
   - 用 `blackdetect` 檢查黑畫面；與段落交界相距 3 個影格以內的黑畫面，會列為警告。

### 6.9 SRT 產生規則（S4）

對齊子程序（stable-ts 強制對齊，語言代碼取自 `[languages.*]` 的 `whisper`）對每一行歌詞回傳起訖時間與每個字的機率。字幕文字一律取自 `lyrics.txt`，辨識出的文字不寫入 SRT；測試會比對 SRT 文字與 `lyrics.txt` 完全相同。處理分三步：

**1. 判定哪些行對得上（`assess`）**

先去掉離群的字：把一行的字依「相鄰兩字相隔超過 `align.max_word_gap`（2 秒）」分群，只保留字數最多的一群（同數取機率總和高的），再以這一群的頭尾修正整行的起訖。一行同時符合以下條件才算對上，否則視為未對齊：

- 有起訖時間，且 `0 ≤ start < end ≤ 歌曲長度 + 0.5`；
- 該行各字機率的平均值 `≥ align.min_confidence`（0.15）；
- 長度 `≥ 演唱字數 × align.min_seconds_per_char`（0.04 秒）；
- 起點不早於上一行對上的結尾（容許 0.05 秒）。

演唱字數：中日韓文字一字算一個，連續的英數字算一個。

**2. 內插未對齊的行（`interpolate`）**

連續的未對齊行，在前後已對齊的行之間依字數比例分配時間，標為 `interpolated`。已對齊各行「每字秒數」的中位數當作唱速：若兩側的空檔遠大於這幾行唱完所需的時間（超過 1.5 倍，例如後面接著一段間奏），不把字幕拉長填滿空檔，而是緊接在上一行後面、用唱速估計長度；歌曲開頭未對齊的行則靠著後面那一行往前排，而不是從 0 秒開始。

**3. 套用顯示規則（`build_cues`）**

```
end_i = min(e_i + tail, s_{i+1} − gap)            結尾延長但不重疊（最後一行以歌曲結尾為限）
若 end_i − s_i < min_duration：end_i = min(s_i + min_duration, s_{i+1} − gap)
```

預設 `tail` 0.3 秒、`min_duration` 0.8 秒、`gap` 0.05 秒（`[subtitle_timing]`）。下一行緊接著開始、放不下最短時間時，至少保證結束不早於開始。間奏不產生字幕；重複的副歌因為 `lyrics.txt` 中各自有一行，會各自對齊。

未對齊（內插）的行超過 `align.max_unaligned_ratio`（15%），代表歌曲可能沒把歌詞唱完：全自動模式換 seed 重新生成歌曲，最多 `song.max_retries`（3）版，最後保留未對齊比例最低的一版；逐步確認模式只提示，由使用者決定要不要按「重新生成歌曲」。字幕校對頁調整後的時間會直接寫回 `lyrics.srt`。
