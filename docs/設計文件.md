## 1. 系統架構與模組職責

```
┌──────────────────────── 介面層 (PySide6) ────────────────────────┐
│ 主視窗：專案清單 │ 精靈六頁（環境/輸入/歌詞/執行/字幕校對/完成）│ 設定 │
└───────────────▲──────────────────────────────┬──────────────────┘
        Qt 訊號（進度、記錄、狀態）            │ 指令（開始/暫停/取消/重跑）
┌───────────────┴──────────────────────────────▼──────────────────┐
│ 流程編排層  PipelineRunner（背景 QThread）                        │
│   狀態機：S1 環境 → S2 歌詞 → S3 歌曲 → S4 字幕 → S5 影片        │
│           → S6 合成 → S7 匯出；續跑、重試、過期標記、暫停點       │
└───────────────┬──────────────────────────────────────────────────┘
                │ 每個階段實作同一介面 Stage
┌───────────────▼──────────────────────────────────────────────────┐
│ 服務層                                                            │
│  ComfyClient（HTTP+WS）  WorkflowTemplate（範本+對應表注入）      │
│  LLMClient（Ollama / Claude / OpenAI 相容）  AlignService（子程序）│
│  FFmpegService   HardwareProbe   LipSyncEngine（InfiniteTalk/LTX）│
└───────────────┬──────────────────────────────────────────────────┘
┌───────────────▼──────────────────────────────────────────────────┐
│ 儲存層  ProjectStore（專案資料夾、project.json 原子寫入）          │
│         AppConfig（config/*.toml）  SecretStore（Windows 認證管理員）│
└──────────────────────────────────────────────────────────────────┘
```

介面層只跟編排層說話；只有服務層的 `ComfyClient` 會連 ComfyUI。

### Stage 共同介面

```python
class Stage(Protocol):
    id: str                                   # "s3_song"
    def check_inputs(self, ctx) -> list[Problem]   # 需要的檔案是否齊全
    def run(self, ctx, reporter) -> StageResult    # 從頭執行
    def resume(self, ctx, reporter) -> StageResult # 從中斷處接續（預設等同 run）
    def outputs(self, ctx) -> list[Path]           # 回報產出檔
```

`ctx` 只提供專案資料夾路徑、設定與服務；階段之間不傳記憶體物件，只讀寫檔案。

## 2. 七階段資料流

| 階段 | 讀取 | 寫入 | 外部呼叫 |
| --- | --- | --- | --- |
| S1 環境偵測 | `config/thresholds.toml`、`workflows/*.requires.json` | `env_report.json` | nvidia-smi、ComfyUI `/system_stats` `/object_info`、ffmpeg |
| S2 歌詞 | `project.json`（內容、曲風、語言、長度、範本） | `lyrics/lyrics.json`、`lyrics/lyrics.txt` | LLM（AI 模式） |
| S3 歌曲 | `lyrics/lyrics.json` | `audio/song.flac`、`audio/yue2_prompt.json` | LLM（Style）、ComfyUI（YuE2） |
| S4 字幕 | `audio/song.flac`、`lyrics/lyrics.txt`、`lyrics/lyrics.json` | `audio/vocals.wav`、`audio/instrumental.wav`、`lyrics/lyrics.srt`、`analysis/sections.json`、`analysis/alignment_report.json` | ComfyUI（人聲分離）、對齊子程序 |
| S5 影片 | `input/photo_原檔`、`audio/vocals.wav`、`audio/song.flac`、`analysis/sections.json` | `input/photo_prepared.png`、`analysis/video_prompt.json`、`analysis/segment_plan.json`、`segments/seg_NNN.mp4`、`output/video_nosub.mp4` | LLM（影像提示詞）、ComfyUI（對嘴引擎）、FFmpeg |
| S6 合成 | `output/video_nosub.mp4`、`lyrics/lyrics.srt`、字幕樣式 | `output/final_mv.mp4` | FFmpeg |
| S7 匯出 | 全部產出 | 專案根目錄的 `final_mv.mp4`、`song.flac`、`lyrics.txt`、`lyrics.srt`、`video_nosub.mp4`（硬連結或複製）、`logs/summary.json` | 無 |

S3 的「歌詞是否唱完」檢查需要 S4 的對齊結果，所以 S3、S4 在編排層是一個重試迴圈：S4 回報未對齊行數超過門檻（預設 >15% 的行）時，編排層把 S3 標成需重試、換 seed 再跑，最多 3 次（可設定）。超過上限後取未對齊最少的那一版，全自動模式記警告繼續，逐步確認模式停下來問。

**依賴與過期規則**（上游改了，下游標為「已過期」）：

```
輸入(內容/曲風/範本) → S2 → S3 → S4 → S5 → S6 → S7
歌詞手動修改         → S3 以下過期
SRT 手動微調         → S6 以下過期
照片/引擎/解析度     → S5 以下過期
字幕樣式             → 只有 S6 以下過期
```

**VRAM 交接**：呼叫 LLM 後讓 Ollama 卸載（`keep_alive: 0`）；每個 ComfyUI 階段結束呼叫 `POST /free`（`unload_models`、`free_memory`）；對齊子程序啟動前先 `/free`，子程序結束即釋放。

`status` 為 `pending`（待執行）、`running`、`done`、`failed`、`stale`（已過期）。開啟專案時若發現 `running`，視為上次被中斷，從該階段 `resume`。寫入一律「寫 `project.json.tmp` → `os.replace`」。金鑰不進這個檔。

### 3.2 `lyrics.json`

```json
{
  "title": "夏夜的風",
  "language": "zh-TW",
  "sections": [
    { "type": "intro",  "lines": [] },
    { "type": "verse",  "lines": ["巷口的燈一盞一盞亮起", "…"] },
    { "type": "chorus", "lines": ["…"] }
  ]
}
```

`type` 六種：`intro`、`verse`、`prechorus`、`chorus`、`bridge`、`outro`。`lines` 為空代表純音樂段落。
`lyrics.txt` 把所有非空行依序一行一句輸出，行號就是字幕編號。

人工輸入解析的標記對照（大小寫、全半形括號都接受）：

| 類型 | 中文 | 英文 | YuE2 標記 |
| --- | --- | --- | --- |
| intro | 前奏 | `[Intro]` | `[Intro]` |
| verse | 主歌 | `[Verse]` | `[Verse]` |
| prechorus | 導歌 | `[Pre-Chorus]` | `[Pre-Chorus]` |
| chorus | 副歌 | `[Chorus]` | `[Chorus]` |
| bridge | 過渡、橋段 | `[Bridge]` | `[Bridge]` |
| outro | 尾奏 | `[Outro]` | `[Outro]` |

YuE2 文件明列的是 Verse/Chorus/Bridge/Outro。`[Intro]`、`[Pre-Chorus]` 是否被接受要在 M2 實測；不接受的話，導歌併入 `[Verse]`、前奏改寫進 Style 描述。這個對照表放在設定檔。

### 3.3 `sections.json`

```json
{
  "duration": 151.36,
  "sections": [
    { "index": 0, "type": "intro",  "start": 0.0,   "end": 12.48, "instrumental": true,  "line_ids": [] },
    { "index": 1, "type": "verse",  "start": 12.48, "end": 41.2,  "instrumental": false, "line_ids": [1,2,3,4] }
  ],
  "silences": [ { "start": 40.62, "end": 41.9 }, { "start": 68.1, "end": 69.0 } ]
}
```

段落邊界取「上一段最後一行的結束」與「下一段第一行的開始」之間的中點。`silences` 是 `vocals.wav` 上 RMS 低於門檻（預設 −40 dBFS）且持續 ≥ 0.4 秒的區間。

### 3.4 工作流對應表 `workflows/<名稱>.map.json`

```json
{
  "template": "yue2_text_to_music.api.json",
  "params": {
    "style":        [ { "node": "12", "input": "style" }, { "node": "14", "input": "style" } ],
    "lyrics":       [ { "node": "12", "input": "lyrics" }, { "node": "14", "input": "lyrics" } ],
    "seed_abc":     [ { "node": "12", "input": "seed" } ],
    "seed_music":   [ { "node": "14", "input": "seed" } ],
    "max_duration": [ { "node": "14", "input": "max_duration" } ],
    "latent_seconds":[ { "node": "10", "input": "seconds" } ],
    "ckpt_name":    [ { "node": "4",  "input": "ckpt_name" } ],
    "filename_prefix":[ { "node": "20", "input": "filename_prefix" } ]
  },
  "outputs": { "audio": { "node": "20", "kind": "audio" } }
}
```

（節點 ID 為示意，實際以轉出的 API 檔為準。）一個參數可以注入多個節點。注入時驗證：節點存在、欄位存在，否則報「對應表第幾項找不到」。程式只認參數名稱。

每個範本另有 `<名稱>.requires.json`：

```json
{
  "nodes": ["YuE2GenerateABC", "YuE2GenerateMusic", "EmptyYuE2LatentAudio"],
  "custom_node_packs": [],
  "models": [ { "file": "yue2_3b_int8_convrot.safetensors", "folder": "models/checkpoints",
                "loader_node": "CheckpointLoaderSimple", "loader_input": "ckpt_name",
                "url": "https://docs.comfy.org/tutorials/audio/yue2/yue2" } ],
  "min_comfyui": "0.36.0"
}
```

模型是否存在以 `/object_info` 中 loader 節點的下拉選項判斷，不直接掃你的磁碟。

### 3.5 歌詞範本 `config/lyric_templates/<id>.toml`

```toml
name = "主歌–副歌–主歌–副歌–過渡–副歌"
style_hint = "口語、畫面感強，副歌重複一句記憶點"
rhyme = "每段偶數行押韻，副歌一韻到底"

[[sections]]
type = "verse"
lines = 4
chars_min = 7
chars_max = 11

[[sections]]
type = "chorus"
lines = 4
chars_min = 6
chars_max = 10
repeat_of = ""        # 之後的副歌填 "chorus_1" 表示重複同一段歌詞
```

內建三個：上述結構、「主歌–導歌–副歌 ×2–尾奏」、「短歌：主歌–副歌–副歌」。
目標長度與行數的換算：預設每行約 4.5 秒、每段間奏 6 秒（設定檔可調）；範本總行數估出的長度若與目標差超過 20%，產生前先提示。

### 3.6 其他

- `alignment_report.json`：每行 `{id, text, start, end, confidence, method: "aligned"|"interpolated"}`，加上整體未對齊比例。
- `segment_plan.json`：每段 `{index, t_start, t_end, f_start, f_end, frames, gen_frames, init: "photo"|"prev_last_frame"}`，見第 6 節。
- `env_report.json`：每項檢查 `{id, label, level: "pass"|"degrade"|"fail", detail, fix}`。

## 5. LLM 提示詞初稿

三組都要求只回 JSON，並以 JSON Schema 約束輸出（Ollama 的 `format`、雲端 API 的結構化輸出）。回傳不合格式時自動重試 2 次，仍失敗則請使用者手動輸入。`{…}` 為程式填入的變數。

### 5.1 歌詞產生

```
你是華語流行歌曲的作詞人。請依下列條件寫一首完全原創的歌詞。

【歌曲內容】{content}
【曲風】{style}
【語言】{language}（歌詞用繁體中文書寫）
【結構】依序寫出以下段落，行數與每行字數必須符合：
{sections_spec}        ← 例：1. 主歌：4 行，每行 7–11 字
【寫作風格】{style_hint}
【押韻】{rhyme}

規則：
1. 必須原創。不得引用、改寫或仿寫任何現有歌曲的歌詞或知名句子。
2. 每一行是一句可以一口氣唱完的歌詞，不要標點符號，不要括號註解。
3. 標示為「重複」的段落，歌詞必須與被重複的段落完全相同。
4. 只寫要唱的字，不要寫演奏指示、和聲或語氣詞提示。
5. 只輸出 JSON，格式：{"title": "...", "sections": [{"type": "verse", "lines": ["...", "..."]}]}
```

單段重新產生時附上整首歌詞，並指定「只重寫第 N 段，其餘保持不變，只回傳該段」。
程式端另外驗證：段落順序、行數、字數範圍、沒有標點；不合就把具體違規點附在重試訊息裡。

### 5.2 YuE2 Style 提示詞

```
請為音樂生成模型 YuE2 寫一行英文的風格描述（style prompt）。

【歌曲內容】{content}
【曲風】{style}
【人聲】{vocal_type}（female vocal / male vocal）
【演唱語言】Mandarin
【歌詞摘要】{lyrics_first_lines}

要求：
1. 一行英文，以逗號分隔的關鍵描述，不超過 60 個英文字。
2. 必須包含：曲風、人聲類型、演唱語言、速度（寫出 BPM 數字）、主要樂器 2–4 種、情緒。
3. 單一主唱，不要合唱團、不要對唱、不要口白。
4. 不要提到任何歌手、樂團或歌曲名稱。
5. 只輸出 JSON：{"style": "...", "bpm": 96}
```

### 5.3 影像提示詞

```
請為「圖片＋音訊轉影片」模型寫一段英文提示詞，畫面是一位歌手在麥克風前演唱。

【曲風與情緒】{style}、{mood}
【照片描述】{photo_description}
【引擎】{engine}

要求：
1. 描述人物外觀（依照片描述，不要改變長相、髮型、服裝）、場景、光線，
   以及在麥克風前演唱的姿態：身體隨音樂輕微擺動、表情投入。
2. 鏡頭固定，單一人物，不切換鏡頭。
3. 不要描述唱歌的速度、節奏、嘴型快慢或說話速度（嘴型由音訊決定）。
4. 60–90 個英文字，一段話。
5. 只輸出 JSON：{"positive": "...", "negative": "..."}
```

`{photo_description}` 的來源：LLM 支援視覺時（Claude、Ollama 的 gemma4 等視覺模型）直接附上照片取得一句描述；不支援時改用輸入頁的人聲類型加通用描述（"a female singer"）。第 3 條對兩個引擎都套用，LTX-2.3 尤其必要。

## 6. 分段與影格計算

### 6.1 基本原則：一律用累計時間換算

設歌曲長度 `D` 秒、影格率 `fps`，總影格數 `N = round(D × fps)`。
切點時間 `t_0 = 0 < t_1 < … < t_k = D`，對應的影格邊界：

```
F_i = round(t_i × fps)        （F_0 = 0，F_k = N）
第 i 段影格數 n_i = F_i − F_{i-1}
```

每個邊界都是從歌曲起點直接換算，不是把各段長度四捨五入後相加，所以 `Σ n_i = N` 恆成立、誤差不會累積。單元測試會用隨機切點驗證這個等式。

### 6.2 切點選擇（LTX-2.3，或 InfiniteTalk 的分段備援）

輸入：`sections.json`、單段上限 `max_seg`（LTX-2.3 預設 10 秒）、下限 `min_seg`（預設 3 秒）。

1. 候選切點 = 所有段落邊界 + 每個人聲靜音區間的中點。段落邊界權重高於靜音中點。
2. 由左而右貪婪選取：從目前位置 `p` 出發，在 `(p + min_seg, p + max_seg]` 內挑最靠後的候選點，同距離時段落邊界優先。
3. 該範圍內沒有候選點（一句長音超過上限）時，在 `[p + 0.6·max_seg, p + max_seg]` 內找 `vocals.wav` 能量最低的 0.1 秒處強制切，並在記錄中標示「非靜音切點」。
4. 最後一段若短於 `min_seg`，併入前一段並重新平分這兩段。

純音樂段落（前奏、間奏、尾奏）同樣切段、同樣由人聲音軌驅動（人聲靜音→不張嘴）。

### 6.3 配合模型的影格數限制

模型對單次生成的影格數有格式限制（Wan 系為 `4k+1`、LTX 系為 `8k+1`；實際值寫在引擎設定裡，以範本與節點定義為準）。對每一段：

```
need_i = n_i               第一段，或以原始照片起始的段
need_i = n_i + 1           以上一段最後一幀起始的段（生成的第 1 幀是重複的那一幀，接合時丟掉）
gen_i  = 滿足模型限制且 ≥ need_i 的最小值
```

- 送出的音訊片段：從 `F_{i-1} / fps` 秒開始，長度 `gen_i / fps` 秒，超出歌曲結尾的部分補靜音。延續段的音訊起點再往前移一幀，對齊重複的那一幀。
- 生成後用 FFmpeg 精確裁成 `n_i` 幀：延續段丟第 1 幀，所有段丟掉尾端多生成的幀。
- 裁完以 `ffprobe -count_frames` 驗證每段幀數等於 `n_i`，不符就視為該段失敗。

### 6.4 連續性與人物漂移

- 延續段的起始影像 = 上一段裁切後最後一幀（無損 PNG 取出）。
- 每 `reset_every` 段（預設 4）改用原始照片起始，抑制累積誤差。重設點只放在段落邊界上：若第 4 段的起點不是段落邊界，就延後到下一個段落邊界才重設。重設處畫面會有一次跳接，放在段落交界處看起來像換鏡頭。

### 6.5 InfiniteTalk 策略

- 預設整首一次送出：`num_frames = N`（調到模型要求的格式後再裁尾），由 WanVideoWrapper 的長片迴圈（`frame_window_size` 81、`motion_frame` 重疊）處理延續。
- 記憶體估算：節點最後回傳整支影片的張量，480p、25 fps、180 秒約 4500 幀 ≈ 21 GB RAM，你的 95 GB 沒問題；720p 約 50 GB，風險高。所以 **720p 或 RAM 不足時直接改走分段**：依 `sections.json` 在段落邊界切（單段上限預設 40 秒），每段各自一次 InfiniteTalk 執行，延續方式同 6.3、6.4。
- 整首模式失敗（OOM 或節點錯誤）時：`/free` → 自動改分段重試一次，並記錄調整內容。
- 整首模式沒有段落檔可續跑，中斷就要重來；所以執行頁在開始前會顯示預估時間，並在設定提供「一律分段」選項。

### 6.6 接合與驗證

1. 各段以相同編碼參數輸出（H.264、yuv420p、固定 fps、相同解析度），用 FFmpeg concat demuxer 接合且不重新編碼；若檢查到參數不一致則改為重新編碼接合。
2. 丟掉各段自帶音軌（`-an`），配上 `song.flac` 轉成的 AAC 48 kHz。
3. 驗證：影片總幀數 = `N`；`|影片長度 − 歌曲長度| ≤ 1/fps`；用 `blackdetect` 檢查交界前後各 3 幀沒有黑幀；用 `mpdecimate` 統計交界處沒有連續重複幀（延續段第 1 幀已丟棄，正常不會有）。

### 6.7 SRT 產生規則（S4）

對每一行（已對齊的起訖 `s_i`、`e_i`）：

```
end_i   = min(e_i + 0.3, s_{i+1} − 0.05)            結尾延長但不重疊
若 end_i − s_i < 0.8：end_i = min(s_i + 0.8, s_{i+1} − 0.05)   至少顯示 0.8 秒
```

未對齊的行：在前後已對齊的行之間，依字數比例內插時間，標記 `interpolated`。間奏不產生字幕。重複的副歌因為 `lyrics.txt` 中各自有一行，會各自對齊。字幕文字逐字取自 `lyrics.txt`，對齊模型的辨識文字不寫入 SRT；測試會比對 SRT 文字與 `lyrics.txt` 完全相同。
