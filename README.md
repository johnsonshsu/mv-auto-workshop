# MV 自動工坊

把「從一個想法到一支帶字幕的歌曲 MV」的流程自動化的桌面 APP。影音生成全部在本機執行，由 APP 透過 ComfyUI 的 API 驅動。

設計說明見 [docs/設計文件.md](docs/設計文件.md)。

## 目前進度

| 階段 | 範圍 | 狀態 |
| --- | --- | --- |
| M1 骨架 | 專案管理、環境偵測、ComfyUI 連線與工作流送出 | 完成 |
| M2 音樂 | 歌詞產生與範本、YuE2 歌曲生成 | 完成 |
| M3 字幕 | 人聲分離、強制對齊、SRT、段落時間表 | 完成 |
| M4 影片 | InfiniteTalk 引擎、分段、接合、配回音軌 | 完成 |
| M5 合成 | 字幕燒入、匯出、完成頁、全自動模式串接 | 完成 |
| M6 強化 | LTX-2.3 引擎、斷點續跑、錯誤處理、字幕校對頁、打包 | 完成 |

目前可以做到：提供音樂內容、曲風、歌詞（AI 產生或自己輸入）與人像照片，按一次「開始製作」，就得到燒好字幕的 `final_mv.mp4`。對嘴引擎有 InfiniteTalk（外掛版、原生版）、LTX-2.3 與 Wan 2.2 S2V 四種可選，**它們的速度與成品特性差很多，開始前請先看[如何選擇對嘴引擎](#如何選擇對嘴引擎開始前必讀)**。

## 需求

- Windows 10/11 64 位元、NVIDIA 顯示卡
- Python 3.11 以上
- FFmpeg（需在 PATH 中；`build.ps1` 會檢查，沒有安裝或無法執行時用 winget 自動安裝並加入 Path，也可依前置作業第 2 項手動安裝）
- ComfyUI Desktop v0.36.0 以上與 Ollama（見下方前置作業）

## 前置作業

安裝本 APP 之前，先準備好 LLM 與 ComfyUI。這兩項沒備齊，APP 能啟動，但「環境檢查」會顯示不通過，製作也無法進行。

### 1. 安裝 Ollama 並下載模型

歌詞、風格描述與照片分析由本機 LLM 產生（預設供應商）。

1. 安裝 [Ollama for Windows](https://ollama.com/download)，並確認它在背景執行（預設位址 `http://127.0.0.1:11434`）。
2. 下載文字模型與視覺模型：

   ```powershell
   ollama pull qwen3.8:27b
   ollama pull gemma4:12b
   ```

   `qwen3.8:27b` 產生歌詞與風格描述；`gemma4:12b` 用來看人像照片、產生影片提示詞。模型名稱可在 APP 設定頁或 `config\default.toml` 的 `[llm]` 修改。

不想裝 Ollama 時，可改用 Claude API 或 OpenAI 相容端點（見 [LLM](#llm)）。

### 2. 手動安裝 FFmpeg（也可交給 build.ps1 自動處理）

`build.ps1` 找不到 FFmpeg 時會自動用 winget 安裝。想自己安裝，或沒有 winget，依下列步驟：

1. **下載**：開啟 <https://www.gyan.dev/ffmpeg/builds/>，在「release builds」下載 `ffmpeg-release-full.7z`（或 `ffmpeg-release-essentials.zip`；`.7z` 需要 7-Zip 解壓縮）。
2. **解壓縮**：解壓縮到固定的位置，例如 `C:\ffmpeg`，解壓後要有 `C:\ffmpeg\bin\ffmpeg.exe` 與 `C:\ffmpeg\bin\ffprobe.exe`。如果多了一層版本資料夾（例如 `C:\ffmpeg\ffmpeg-7.1-full_build\bin`），請記下實際的 `bin` 路徑。放好後不要再搬動。
3. **加入系統 Path**：
   1. 按 Windows 鍵，搜尋「編輯系統環境變數」並開啟。
   2. 按「環境變數」。
   3. 在下方「系統變數」找到 `Path`，選取後按「編輯」。
   4. 按「新增」，貼上 `bin` 資料夾的完整路徑（例如 `C:\ffmpeg\bin`），按「確定」關閉所有視窗。系統變數需要系統管理員權限；只想給自己使用，可加在上方的「使用者變數」。

   或以**系統管理員身分**開啟 PowerShell 執行（路徑請換成你的 `bin`）：

   ```powershell
   $bin = "C:\ffmpeg\bin"
   [Environment]::SetEnvironmentVariable("Path", [Environment]::GetEnvironmentVariable("Path", "Machine") + ";$bin", "Machine")
   ```
4. **驗證**：**重新開啟**一個新的 PowerShell（已開著的視窗讀不到新的 Path），執行：

   ```powershell
   ffmpeg -version
   ffprobe -version
   ```

   兩個都顯示版本資訊就完成了。顯示「無法辨識」代表路徑不對，或視窗沒有重新開啟。

### 3. 安裝 ComfyUI Desktop 並啟動

1. 安裝 [ComfyUI Desktop](https://www.comfy.org/download)（v0.36.0 以上），完成首次設定。
2. **先啟動一個 ComfyUI 實例並保持執行**，本 APP 透過 `http://127.0.0.1:8188` 連線。連線位址可在 `config\default.toml` 修改。
3. 使用 InfiniteTalk（外掛版）時，要在 ComfyUI Desktop 的啟動參數加上 `--disable-dynamic-vram` 後重新啟動，否則套用 LoRA 時 ComfyUI 會當掉。

### 4. 補齊各工作流缺少的模型與節點

每個工作流需要的節點、自訂節點套件與模型檔，各列在 `workflows\<名稱>.requires.json`。**最簡單的做法**：啟動 APP 後看「環境檢查」頁，缺什麼就會逐項列出，並附上下載位置與應放的資料夾。依下表補齊後，重新檢查直到顯示通過（`models\` 指 ComfyUI 的 models 資料夾）。

| 功能 | 需要的自訂節點套件 | 主要模型檔（放進 `models\` 下的子資料夾） |
| --- | --- | --- |
| 歌曲生成（YuE2，必要） | 無 | `checkpoints`：`yue2_3b_int8_convrot.safetensors` |
| 人聲分離（必要） | ComfyUI-MelBandRoFormer（kijai）。在「自訂節點管理器」搜尋 `MelBandRoFormer`，安裝並確認已啟用，再重新啟動 ComfyUI；沒有時改用 Demucs 節點 | `diffusion_models`：`MelBandRoformer_fp16.safetensors`（[Kijai/MelBandRoFormer_comfy](https://huggingface.co/Kijai/MelBandRoFormer_comfy)） |
| InfiniteTalk（外掛版） | ComfyUI-WanVideoWrapper（kijai）、ComfyUI-VideoHelperSuite | `diffusion_models`：Wan2.1 I2V 14B 480p（fp8 KJ）與 InfiniteTalk Single（fp8 KJ）；`loras`：lightx2v I2V 480p；`vae`：Wan2_1_VAE_bf16；`text_encoders`：umt5-xxl-enc-bf16；`clip_vision`：clip_vision_h |
| InfiniteTalk（原生版） | ComfyUI-VideoHelperSuite | `diffusion_models`：Wan2.1 I2V 14B 480p（fp8 KJ）；`model_patches`：wan2.1_infiniteTalk_single_fp16；`loras`：lightx2v I2V 480p；`text_encoders`：umt5_xxl_fp8_e4m3fn_scaled；`vae`：Wan2_1_VAE_bf16；`audio_encoders`：wav2vec2-chinese-base_fp16 |
| LTX-2.3 | ComfyUI-VideoHelperSuite | `checkpoints`：ltx-2.3-22b-dev-fp8；`text_encoders`：gemma_3_12B_it_fp4_mixed；`loras`：ltx 2.3 distilled lora；`latent_upscale_models`：ltx-2.3-spatial-upscaler-x2 |
| Wan 2.2 S2V | ComfyUI-VideoHelperSuite | `diffusion_models`：wan2.2_s2v_14B_fp8_scaled；`loras`：wan2.2_t2v_lightx2v_4steps_lora_v1.1_high_noise；`text_encoders`：umt5_xxl_fp8_e4m3fn_scaled；`vae`：wan_2.1_vae；`audio_encoders`：wav2vec2_large_english_fp16 |

- 完整檔名與下載連結以 `workflows\*.requires.json` 為準。LTX-2.3 的檔案依 [ComfyUI 官方教學](https://docs.comfy.org/tutorials/video/ltx/ltx-2-3) 下載。
- 本機檔名與清單不同但符合對應的檔名規則時，APP 會自動改用你本機的檔名。
- 不需要四個引擎都裝：只補齊你要用的那一個，環境檢查會顯示「可用的對嘴引擎」。想先試，建議從一個引擎開始（比較見[如何選擇對嘴引擎](#如何選擇對嘴引擎開始前必讀)）。
- 缺少自訂節點套件時，在 ComfyUI 的「自訂節點管理器」搜尋套件名稱（例如 `MelBandRoFormer`）安裝，並確認右下角的開關是啟用狀態，安裝後重新啟動 ComfyUI。
- APP 不會修改 ComfyUI 的安裝內容，缺少的項目要自己下載。

## 安裝

依序執行：

```powershell
.\build.ps1                     # 1. 打包，產出 dist\MVAutoWorkshop
cd dist\MVAutoWorkshop          # 2. 進入打包資料夾
.\setup_align_env.ps1           # 3. 建立字幕對齊環境（只需一次，約 3 GB）
.\MVAutoWorkshop.exe            # 4. 啟動 UI
```

- 第 1 步會先檢查 FFmpeg（`ffmpeg`、`ffprobe`）。沒有安裝或無法執行時，用 winget 安裝 `Gyan.FFmpeg` 並加入 Path：以系統管理員身分執行會加入系統（全域）Path，否則只能加入使用者 Path 並顯示警告。已開啟的終端機要重新開啟才讀得到新的 Path。
- 第 1 步找不到 `.venv` 時（例如剛 clone 專案）會自動建立並安裝所需套件，不必手動處理。
- 第 3 步會在 `dist\MVAutoWorkshop\align-env` 安裝 torch 與 stable-ts。重新執行 `build.ps1` 不會刪除 `align-env`，不必重做。
- 第一次執行字幕階段時，還會下載 Whisper large-v3 模型（約 3 GB）到 `%USERPROFILE%\.cache\whisper`，只需下載一次。
- 重新打包前請先關閉執行中的 `MVAutoWorkshop.exe`。

## 執行

先啟動 ComfyUI Desktop，再執行 `dist\MVAutoWorkshop\MVAutoWorkshop.exe`。

1. 按「＋ 新專案」輸入名稱。專案會建立在設定的專案資料夾（預設 `D:\MV專案`）。
2. 選取專案後會自動做環境檢查，逐項顯示通過、需降規或不通過，以及補救方式。
3. 按「送出測試工作流」會用 YuE2 產生約 10 秒的音樂，音檔存到專案的 `logs\test_yue2.flac`。
4. 到「輸入」頁填寫音樂內容、曲風、語言、人聲與聲線，選擇歌曲長度、歌詞來源、歌詞範本與對嘴引擎（怎麼選見[如何選擇對嘴引擎](#如何選擇對嘴引擎開始前必讀)），按「開始製作」。
5. 「執行」頁顯示各階段進度與記錄。150 秒的歌在 RTX 5090 Laptop 上約需 4 分鐘。
6. 「歌詞」頁可以修改歌詞、整首重新產生，或只重新產生游標所在的段落。儲存修改後，歌曲會標為「已過期」，回到執行頁按「繼續」就會重新生成。

執行模式：

- **全自動**：一路跑到目前可用的最後一個階段。
- **逐步確認**：歌詞產生後、歌曲生成後各停一次，檢查或修改後按「繼續」。

歌詞來源選「自己輸入」時，到歌詞頁貼上歌詞並儲存。段落標記中英文都可以：`[主歌]`、`[導歌]`、`[副歌]`、`[過渡]`、`[前奏]`、`[尾奏]`，或 `[Verse]`、`[Pre-Chorus]`、`[Chorus]`、`[Bridge]`、`[Intro]`、`[Outro]`。

## 字幕

歌曲完成後，字幕階段會：

1. 把歌曲上傳到 ComfyUI，用 MelBandRoFormer 分離出人聲與伴奏（沒有模型時改用 Demucs 節點）。
2. 請 ComfyUI 釋放模型，再啟動獨立的對齊程序，把每一行歌詞對到人聲上的時間。
3. 產生 `lyrics\lyrics.srt`、`analysis\sections.json`（段落時間與人聲靜音間隙）與 `analysis\alignment_report.json`（每行的時間、信心值、是對齊還是內插）。

字幕文字一律取自歌詞，不使用語音辨識的結果。對不上人聲的行會用前後行內插時間，並在執行頁顯示警告。

全自動模式下，若對不上的行超過 15%（`config/default.toml` 的 `align.max_unaligned_ratio`），代表歌曲可能沒把歌詞唱完，會換 seed 重新生成歌曲並重做字幕，最多 3 版，最後保留對得最好的一版。逐步確認模式不會自動重試，可以按執行頁的「重新生成歌曲」。

## 對嘴影片

字幕完成後，影片階段會：

1. 把照片裁成影片尺寸（另存 `input\photo_prepared.png`，原圖不動），並請 LLM 看照片寫影像提示詞。
2. 依段落時間表切段：切點優先選段落邊界，其次是人聲靜音處，每段不超過引擎的上限（InfiniteTalk 60 秒、Wan 2.2 S2V 30 秒、LTX-2.3 10 秒）。每段的影格數都從歌曲起點以累計時間換算，所以各段加起來一定等於「歌曲長度 × fps」。
3. 逐段送到 ComfyUI 生成。第一段從照片開始，之後每段怎麼接由輸入頁的「分段銜接」決定（見下一節）。每段完成就存到 `segments\`，並記在 `project.json`。
4. 用 FFmpeg 接合各段，丟掉各段自帶的音軌，配回完整歌曲，輸出 `output\video_nosub.mp4`，並檢查總影格數與歌曲長度一致。

**這個階段最花時間，而且各引擎差很多。** 在 RTX 5090 Laptop 上以 480p 實測，一首 150 秒的歌用 InfiniteTalk（外掛版）要 3 小時 54 分，用 LTX-2.3 約 17 分鐘。執行頁會顯示預估剩餘時間。

中途取消、關閉 APP 或當機都沒關係：重新開啟專案按「繼續」，已完成的段落會跳過。只要照片、歌曲、段落時間表、引擎與解析度沒變，就會沿用已完成的段落；其中任何一項變了，就會整個重新生成。想用同樣的輸入重新生成影片，刪除專案的 `segments` 資料夾即可。

InfiniteTalk（外掛版）可調整的設定在 `config/default.toml` 的 `[engines.infinitetalk]`：

| 設定 | 說明 |
| --- | --- |
| `max_segment_seconds` | 單段長度上限。越短，中斷時損失越少，但段落交界越多 |
| `steps` | 取樣步數。步數越少越快，畫質可能下降 |
| `blocks_to_swap` | 留在系統記憶體的模型區塊數。越大越省 VRAM、越慢 |
| `reset_every` | 每幾段改回以原始照片起始，抑制人物越來越不像；重設只發生在段落邊界 |

使用 InfiniteTalk（外掛版）時，ComfyUI 必須以 `--disable-dynamic-vram` 啟動，否則 WanVideoWrapper 套用 LoRA 時會當掉；環境檢查會確認這一點。

## 如何選擇對嘴引擎（開始前必讀）

**這是製作前最重要的一個決定。** 四個引擎的速度最多相差十倍以上，成品的觀感也不一樣，而且換引擎就要把整支影片重新生成。請先看完這一節再到輸入頁選擇。

### 四個引擎的限制

以下都是在 RTX 5090 Laptop（24 GB 顯示記憶體）、480p、同一張照片上的實測。**粗體是選擇時最該看的三項。**

| | InfiniteTalk（外掛版） | InfiniteTalk（原生版） | LTX-2.3 | Wan 2.2 S2V |
| --- | --- | --- | --- | --- |
| **每 1 秒影片要算多久** | **約 94 秒** | **約 55 秒** | **約 7 秒** | **約 19 秒** |
| **一首 150 秒的歌** | **3 小時 54 分（實測）** | 約 2 小時多（推估） | **17 分鐘（實測）** | 約 48 分鐘（由 182 秒歌曲實測 58 分鐘換算） |
| **每段長度上限** | **60 秒** | **60 秒** | **10 秒** | **30 秒** |
| 150 秒歌曲大約分成幾段 | 3 段 | 3 段 | 22 段 | 7 段 |
| 影格率 | 25 fps | 25 fps | 24 fps | 16 fps |
| 480p 的實際尺寸 | 832×480 | 832×480 | 896×512 | 832×480 |
| 嘴型 | 明顯，像在唱歌 | 明顯，像在唱歌 | 明顯 | 幅度小，比較像在說話 |
| 動作幅度 | 小 | 小 | 大 | 中 |
| 人物穩定度 | 高 | 高 | 靠段尾回到照片來維持 | 高（每個區塊都以照片為參考） |
| 段與段之間 | 接續上一段的最後一幀 | 接續上一段的最後一幀 | 接續上一段的最後一幀，段尾回到照片的樣子 | 預設每段重新從照片開始，會跳接 |
| 整首歌實測過 | 有 | 沒有，只測過 6 秒 | 有 | 有 |
| 720p | 沒有實測 | 沒有實測 | 實測可用（1344×768，21 分鐘） | 沒有實測 |

每個引擎受限的地方不一樣：

- **InfiniteTalk（外掛版與原生版）** 是為長片段設計的，一段可以到 60 秒，整首歌只有兩三個交界，嘴型也最像在唱歌。代價是慢。兩個版本用的是同一個模型：外掛版由 kijai 的 ComfyUI-WanVideoWrapper 執行，原生版由 ComfyUI 內建的節點執行，實測原生版快了四成左右。
- **LTX-2.3** 一次生成一整段，段越長越吃顯示記憶體、也越容易走樣，所以每段限制在 10 秒，一首歌要接二十幾段。它最快，但交界最多；每 5 到 10 秒人物會在換氣處回到照片的表情一次，看久了可能察覺這個規律。超過 10 秒的分段沒有實測過。
- **Wan 2.2 S2V** 人物很穩，但有兩個限制。第一，**連續接續越久畫面越劣化**：對比與銳利度會逐漸過頭，實測連續約 25 秒還正常，60 秒看得出來，整首 182 秒一路接續到後半已經不能用。所以預設每一段（最長 30 秒）都重新從照片開始，段與段之間會直接跳接，像換鏡頭。第二，它固定是 16 fps，動作比其他引擎略不流暢，嘴型幅度也比較小。

### 該選哪一個

| 情境 | 建議 | 原因 |
| --- | --- | --- |
| 第一次使用，想先看整個流程跑不跑得通 | LTX-2.3 | 二十分鐘內看到成品，有問題可以馬上調整 |
| 還在試歌詞、曲風、照片、字幕樣式 | LTX-2.3 | 每換一次照片或歌曲，影片都要整個重做，慢的引擎試不起 |
| 歌曲和照片都定案了，要做最終成品 | InfiniteTalk（原生版或外掛版） | 交界少、人物穩定、嘴型最像在唱歌 |
| 想要 InfiniteTalk 的效果但希望快一點 | InfiniteTalk（原生版） | 短片段實測比外掛版快四成；但整首歌還沒有跑過，穩定度不如外掛版有把握 |
| 最在意穩定、不想冒險 | InfiniteTalk（外掛版） | 整首歌實測過，結果已知 |
| 不想等三四個小時，又覺得 LTX-2.3 的交界太多 | Wan 2.2 S2V | 一小時內完成，整首只有六七個交界，人物穩定；但交界處會跳接，嘴型較小 |
| 希望人物表情和動作豐富一點 | LTX-2.3 | 動作幅度明顯比較大 |
| 需要 720p | LTX-2.3 | 只有它實測過 720p |
| 顯示記憶體不到 24 GB | 先用 LTX-2.3、480p 試 | 較小的顯示卡都沒有實測過 |

**建議的做法：先用 LTX-2.3 把歌曲、歌詞、字幕都調到滿意，再換成 InfiniteTalk 做最後一版。** 換引擎只會重做影片與字幕合成，歌詞、歌曲和字幕時間都會保留。

### 各自的優缺點

**InfiniteTalk（外掛版）**

- 優點：人物從頭到尾穩定；整首只有兩三個交界；嘴型明顯；整首歌實測過。
- 缺點：最慢，一首歌要三到四小時；動作幅度小；需要安裝 ComfyUI-WanVideoWrapper，而且 ComfyUI 必須以 `--disable-dynamic-vram` 啟動（環境檢查會確認）。

**InfiniteTalk（原生版）**

- 優點：與外掛版同一個模型、同樣的效果，短片段實測快四成；只用 ComfyUI 內建的節點，不需要外掛。
- 缺點：仍然要兩個小時左右；整首歌沒有跑過，長片段的記憶體用量與穩定度還不確定；也沒有測過不加 `--disable-dynamic-vram` 啟動時的情況。

**LTX-2.3**

- 優點：最快；表情與動作豐富；720p 實測可用。
- 缺點：每段最多 10 秒，交界多；人物要靠段尾回到照片來維持，會有週期性回到同一個表情的感覺；在人聲中被迫切開的段落（通常是超過 10 秒沒有換氣的長句）銜接會比較明顯。

**Wan 2.2 S2V**

- 優點：速度居中；人物穩定；一段可以到 30 秒，交界少。
- 缺點：不能長時間連續接續，否則畫面劣化，所以段與段之間預設是跳接；16 fps；嘴型幅度小，比較像說話而不是唱歌；實測中 ComfyUI 曾在整首歌的第 6 段停止回應（另一次整首 8 段則正常跑完），原因還不清楚，遇到時重新啟動 ComfyUI 後按「繼續」即可從那一段接著做。

### 照片對引擎的影響

- 四個引擎都需要清楚的正面或微側面人像，臉不要太小。
- 用 LTX-2.3 時，每段結尾都會回到照片的表情。照片若是明顯的笑容，和唱歌中的表情落差大，回歸的痕跡會比較明顯；**嘴巴微張或表情中性的照片效果比較自然**。這一點是依原理推斷的，沒有換照片實測比較過。
- 用 Wan 2.2 S2V 時，每段都從接近照片的姿勢重新開始，照片的姿勢越自然，跳接越不明顯。

### 分段銜接（下一段從哪裡開始）

整首歌要分成好幾段生成再接起來。輸入頁的「分段銜接」決定每一段從哪個畫面開始，以及怎麼防止人物越接越不像。換引擎時會自動帶入該引擎的預設值。

選好對嘴引擎後，下方會顯示這個引擎**每段最長幾秒、這首歌大約分成幾段**，可以據此決定銜接方式：段數越多，「每幾段回到照片一次」的影響越大。歌曲還沒生成時以 150 秒估算；歌曲已經生成就用實際長度；專案已經用這個引擎分過段，則直接顯示實際的段數與交界數。切點要落在換氣或段落交界處，所以生成前只能給範圍。

同一個位置還會顯示**預估時間**：以 30 秒的影片為標準，要算多久；歌曲已經生成時再加上整首的時間。切換引擎或解析度會立刻更新。預估只算對嘴影片這個階段，速度取自 `config/default.toml` 各引擎的 `[engines.<引擎>.speed]`（每 1 秒影片要算幾秒，RTX 5090 Laptop 的實測值）；顯示卡不同的話請依自己的實際速度修改。專案已經用同一個引擎、同一個解析度生成過，就改用那次的實際速度。沒有實測過的組合（例如 Wan 2.2 S2V 的 720p）會顯示無法估算。

| 選項 | 行為 | 可以調整 |
| --- | --- | --- |
| 以上一段的最後一幀起始，段尾回到照片的樣子 | 畫面連續不跳接；人物在換氣處平順地回到照片的樣子，所以會週期性出現同一個表情。**只有 LTX-2.3 支援**，也是它的預設 | 每幾段回到照片一次；貼近照片的程度 |
| 定期改以原始照片起始 | 回到照片的那一刻畫面直接跳接，像換鏡頭；其餘的段接續上一段。InfiniteTalk（每 4 段）與 Wan 2.2 S2V（每段）的預設 | 每幾段一次 |
| 一律以上一段的最後一幀起始 | 完全不回到照片。LTX-2.3 段數多，後段的人物很可能已經不像本人；Wan 2.2 S2V 則會越來越失真 | 無 |

- 「每幾段一次」調大：動作比較自由、跳接或回歸的次數變少，但人物比較容易走樣（Wan 2.2 S2V 則是畫面劣化）。
- 「貼近照片的程度」預設 0.8：1.0 是段尾完全貼齊照片；調低只是靠近照片，回歸的痕跡較淡，但人物可能慢慢走樣。0.8 以外的數值沒有實測過。
- 回到照片或跳接都只安排在換氣或段落交界處；遇到在人聲中被迫切開的地方，會延後到下一個換氣處。
- Wan 2.2 S2V 的「接續上一段」不是用最後一幀當開頭，而是把上一段最後 73 幀交給模型當動作參考，照片仍然是每個區塊的參考影像。
- 這些選項存在專案裡；預設值在 `config/default.toml` 各引擎的 `reset_every`、`end_anchor`、`anchor_strength`。改了任何一項，影片都會整個重新生成。

切換引擎、照片或解析度後，影片也會整個重新生成。想用同樣的輸入重新生成，按執行頁的「重新生成影片」。

## 暫停、取消與續跑

- **暫停**：目前這一段影片（或這個階段）跑完後停下，不浪費已經算到一半的東西。
- **取消**：立即中斷目前的生成；只會動到本 APP 送進 ComfyUI 的工作。
- 兩者之後都可以按「繼續」。關閉 APP 或當機後重新開啟專案，也是按「繼續」從未完成的地方接著跑。

## 字幕校對

字幕對齊完成後，「字幕校對」頁會顯示人聲波形與每一則字幕的方塊：

- 紅色方塊的時間是內插的（那一行對不上人聲），黃色是對齊信心偏低。
- 拖曳方塊邊緣調整起訖，拖曳中間整則移動；也可以用按鈕每次微調 0.05 秒。字幕不能互相重疊。
- 「試聽這一行」預設播放分離後的人聲，也可以切換成完整歌曲。
- 按「儲存並重新燒字幕」會寫回 `lyrics.srt`；影片已經生成的話，只會重新燒字幕與匯出。

逐步確認模式會在字幕產生後停在這一頁。

## 字幕合成與匯出

影片完成後，會用 FFmpeg 把 `lyrics.srt` 燒進影片，再把交付檔案放到專案資料夾最上層：

| 檔案 | 內容 |
| --- | --- |
| `final_mv.mp4` | 燒入字幕的完整 MV（H.264、AAC 48 kHz） |
| `video_nosub.mp4` | 尚未燒字幕的影片 |
| `song.flac` | 完整歌曲 |
| `lyrics.txt`、`lyrics.srt` | 歌詞與帶時間的字幕檔 |
| `logs\summary.json` | 各階段耗時與警告摘要 |

最上層的檔案是 `output\`、`audio\`、`lyrics\` 內同名檔案的硬連結，不會多佔磁碟空間。

完成後會自動跳到「完成」頁，可以預覽影片、開啟輸出資料夾、查看各階段耗時與警告。

## 重新開始

想用同一個專案重新設計時，按輸入頁左下角的「重新開始…」，有兩種方式：

| | 只回復預設值 | 全部清除 |
| --- | --- | --- |
| 音樂內容、曲風、語言、聲線、長度、引擎、解析度、執行模式、字幕樣式 | 回到預設值 | 回到預設值 |
| 照片 | 保留 | 刪除 |
| 已產生的歌詞、歌曲、字幕、影片、記錄 | 留在資料夾，標成已過期，下次製作時重新產生 | 刪除，無法復原 |

「全部清除」會再確認一次，只刪這個專案資料夾裡的內容，專案本身（名稱與資料夾）會保留。有工作在執行時不能重新開始。

## 執行結果報告

完成頁的「匯出報告…」可以把這次製作的結果存成 HTML 或 Markdown（在存檔視窗選擇格式），預設放在專案資料夾的 `report.html`，存好後會自動開啟。內容包含：

- 總覽：狀態、執行模式（全自動或逐步確認）、總耗時、成品的解析度與長度、每 1 秒影片花了幾秒。
- 各階段的執行方式與耗時：用了哪個模型或引擎、生成幾次、分幾段、對上幾行歌詞，以及開始時間、耗時、佔總時間的比例。
- 對嘴影片各段的時間範圍、影格數與耗時。
- 輸入設定。
- 提示詞：一開始輸入的音樂內容與曲風，以及 AI 據此寫出的歌曲風格描述和影像提示詞（這些每次製作都可能不同）。
- 這次的歌詞：歌名與各段內容（每次製作的歌詞都可能不同，所以一併留在報告裡）。
- 警告與錯誤。

專案還沒跑完也可以匯出，未完成的階段會標示狀態。各階段的耗時是該階段最後一次執行的時間，重跑過的階段不會累計先前的時間。

## 字幕樣式

輸入頁與完成頁都有「字幕樣式…」按鈕，隨時可以改；改完只會重新燒字幕與匯出，不會重新生成歌曲或影片。視窗右側會用影片的一格畫面（還沒有影片時用照片）即時預覽。

| 項目 | 說明 |
| --- | --- |
| 範本 | 一鍵套用一組顏色與描邊：白字黑邊、黃字黑邊、白字加陰影、半透明底框、KTV 白字藍邊。可在 `config/default.toml` 的 `[[subtitle.presets]]` 增減 |
| 字型 | 這台電腦上所有含繁體中文字、而且 FFmpeg 找得到的字型。同一套字型的各種粗細（例如 Noto Sans TC Light）FFmpeg 不認得，不會列出 |
| 大小、邊距、描邊粗細 | 都是「佔畫面高度的百分比」，換解析度時看起來一樣大 |
| 字體 | 粗體、斜體 |
| 位置 | 置底、置頂、畫面正中，一律水平置中 |
| 文字背後 | 無、陰影、半透明底框，可設定顏色與不透明度 |

預設是置底、白字黑邊、Noto Sans TC；找不到字型時改用微軟正黑體並顯示警告。預設值在 `config/default.toml` 的 `[subtitle]`。

## 歌曲語言與聲線

輸入頁可以選歌曲語言與聲線，兩者都會自動寫進 YuE2 的風格描述：

```text
English, husky female vocal, emotional pop ballad, 72 BPM, piano, strings, acoustic guitar, intimate, polished
```

風格描述的組成是「語言、聲線＋男女聲、曲風、速度、樂器、其他特徵」。語言、男女聲與聲線由程式依你的選擇填入；曲風、速度、樂器由 LLM 依音樂內容與曲風範本決定。實際送出的風格描述會顯示在執行頁的記錄裡，也存在 `audio\yue2_prompt.json`。

| 語言 | 歌詞 | 備註 |
| --- | --- | --- |
| 國語 | 繁體中文，簡體字自動轉繁體 | |
| 英語 | 以單字數控制每行長度 | |
| 日語 | 漢字與假名混寫，以字數控制每行長度 | |
| 粵語 | 繁體中文、粵語用字 | 實驗性：YuE2 官方沒有明列粵語 |

- 歌詞範本的「每行字數」是以中文寫的，其他語言會自動換算（英語乘 0.7 算單字數，日語乘 1.5）。
- 字幕對齊會用對應語言的模型設定；字幕字型 Noto Sans TC 可以顯示日文假名。
- 聲線選「自動」時由 LLM 依歌曲內容決定；選了特定聲線（溫暖、清亮、沙啞、空靈等）就以你選的為準。
- 改語言會重新產生歌詞；只改聲線或男女聲只會重新生成歌曲。
- 語言與聲線的清單在 `config/default.toml` 的 `[languages.*]` 與 `[[voices]]`，可以自己增減。
- InfiniteTalk 用來驅動嘴型的語音模型是中文的，其他語言的嘴型準確度沒有驗證過。

## 歌曲長度

不需要自己猜秒數。輸入頁的「歌曲長度」有兩種：

| 模式 | 行為 |
| --- | --- |
| 自動（預設） | 由 AI 決定，唱完為止。給 YuE2 一個寬鬆的上限（300 秒），歌曲唱完整份歌詞後會自己結束，實際多長就是多長 |
| 設定上限（最多 N 秒） | 歌曲不會超過 N 秒；唱完時還不到 N 秒，就以實際長度為準 |

實測：同一份 22 行的歌詞，上限給 300 秒時歌曲在 151 秒自己結束；慢歌（72 BPM）22 行則是 163 秒。

**自動模式**下，如果歌曲長度剛好等於上限，代表是被切斷而不是唱完，會把上限放寬（300 → 450 → 600 秒）再生成。

**上限模式**為了不產生唱到一半的歌，會做三件事：

1. AI 寫歌詞前，先依曲風的速度估算唱完需要多久；放不下就從歌詞範本的後面拿掉段落（通常是重複的副歌或過渡），並在執行頁說明拿掉了什麼。
2. 自己輸入的歌詞太長時，歌詞頁與執行頁會標示「估計需要約 X 秒，超過上限」。
3. 生成後若仍碰到上限，換 seed 重試最多 3 次；還是碰到上限，就在結尾加 3 秒淡出並顯示警告。上限不會被自動放寬。

估算方式是「一行歌詞約兩小節」，再加上前奏、尾奏與段落間的過門。這是估計值，實際長度由 YuE2 決定；下游的字幕與影片一律以歌曲的實際長度為準。相關設定在 `config/default.toml` 的 `[song]`。

## LLM

歌詞與風格描述由 LLM 產生，在設定頁選擇供應商：

| 供應商 | 說明 |
| --- | --- |
| 本機 Ollama（預設） | 不需金鑰。每個階段用完會主動卸載模型，把 VRAM 讓給 ComfyUI |
| Claude API | 需要另外安裝 `anthropic` 套件：`.\.venv\Scripts\python.exe -m pip install anthropic`，並在設定頁填金鑰 |
| OpenAI 相容端點 | 在設定頁填端點位址、模型名稱與金鑰 |

金鑰存在 Windows 認證管理員。提示詞放在 `prompts/`，可以直接修改。

## 歌詞範本與曲風範本

- 歌詞範本定義段落順序、每段行數、每行字數範圍、押韻與寫作風格。內建三個在 `config/lyric_templates/`；在輸入頁按「管理範本…」可以新增、編輯、刪除，自訂的存在 `%APPDATA%\MVAutoWorkshop\lyric_templates\`。
- `repeat_of = 2` 表示這一段與第 2 段歌詞完全相同（例如重複的副歌），LLM 只需要寫不重複的段落。
- 曲風範本在 `config/style_presets.toml`，每個曲風附一段給 YuE2 用的英文提示；輸入頁也可以直接輸入清單以外的曲風。

不開介面也可以從命令列檢查：

```powershell
.\.venv\Scripts\python.exe -m app.cli env
.\.venv\Scripts\python.exe -m app.cli test-workflow 輸出資料夾
```

## 設定

- `config/default.toml`：解析度、fps、模型檔名、連接埠等預設值。
- `config/thresholds.toml`：各模型的硬體門檻（最低／建議的 VRAM 與記憶體）及出處。
- 在設定頁改的值存在 `%APPDATA%\MVAutoWorkshop\settings.json`，會覆蓋預設值。

ComfyUI 位址會自動偵測（先試連接埠 8000，再試 8188），並記住上次成功的位址；也可以在設定頁手動指定。

## 工作流範本

`workflows/` 內每個工作流有三個檔案：

| 檔案 | 內容 |
| --- | --- |
| `<名稱>.api.json` | API 格式的工作流（在 ComfyUI 用 File → Export Workflow (API) 匯出） |
| `<名稱>.map.json` | 對應表：參數名稱 → 節點 ID 與輸入欄位 |
| `<名稱>.requires.json` | 需求清單：節點、自訂節點套件、模型檔與下載位置，供環境檢查使用 |

要換成自己調好的工作流：把匯出的 API 格式 JSON 放進 `workflows/`，再修改對應表的 `template` 與各參數指向的節點 ID 與欄位即可，不必改程式。

Wan 2.2 S2V（`wan22_s2v`）與 InfiniteTalk 原生版（`infinitetalk_native`）的範本只包含第一個區塊：這兩個模型一次只生成約 3 到 5 秒，較長的片段是由程式在送出前把同一組節點重複接上去（`app/services/engines.py`），所以這兩個範本換掉節點編號時，程式裡對應的編號也要一起改。

## 本 APP 會動到的地方

- 專案資料夾（預設 `D:\MV專案`）與 `%APPDATA%\MVAutoWorkshop\settings.json`。
- ComfyUI 的 output 資料夾：生成的檔案放在 `mv_workshop\` 子資料夾，APP 下載後不會自動刪除。
- 不修改 ComfyUI 的安裝內容。缺少模型或節點時只列出清單與下載位置。
- 取消時只移除本 APP 送進佇列的工作，不動你自己在 ComfyUI 排的工作。

## 打包成執行檔

```powershell
.\build.ps1
```

步驟見上方[安裝](#安裝)。`build.ps1` 會安裝 PyInstaller 並產出 `dist\MVAutoWorkshop\`（約 185 MB），裡面有 `MVAutoWorkshop.exe`，以及可以直接編輯的 `config`、`workflows`、`prompts`。

要搬到別台電腦：複製整個 `MVAutoWorkshop` 資料夾，到目標電腦執行一次 `.\setup_align_env.ps1`（需先安裝 Python 3.11 以上）。torch 與 stable-ts 太大（約 5 GB），所以沒有包進執行檔。也可以改在 `config\default.toml` 的 `align.python` 填入已安裝 stable-ts 的 `python.exe`。沒有對齊環境時，其他階段照常運作，字幕階段會提示要先執行這個腳本。

目標電腦同樣需要 ComfyUI、FFmpeg，以及（使用本機 LLM 時）Ollama。
